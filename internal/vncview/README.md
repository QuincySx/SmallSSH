# Bundled noVNC viewer

Start accepts only an allocated loopback SSH tunnel; StartDirect uses the native-selected fixed TCP target. Each viewer has a random capability path, loopback listener, Host/Origin restrictions, bounded frames and one WebSocket. Closing its owner closes listener and sockets. No HTTP argument can retarget it.

The native frontend defaults to a workspace tab with a private embedded WebView. Selection, drag, split and canvas changes retain the same page and transport. The connection dialog has no presentation selector. Full screen retains the same WebView and transport. The release viewer does not grant Go RPC trust; MyGo development mode has its own loopback policy.

Authentication is negotiated by pinned noVNC. ConfigureCredentials supplies only a destination-matched owner credential. Successful manual login may save via an Origin-checked, bounded POST callback bound by native code to the host/target/mode. The callback uses the owner's authenticated IPC and encrypted vault. Credentials are served only by the private no-store configuration endpoint, never URL, static HTML, public summaries or logs. Failed authentication never saves and clears the automatic retry candidate. The native connection dialog can forget saved credentials. Closing the viewer clears its copy.

The viewer has a 40px right-side toolbar with 32px icon targets and no top header. All eight actions, including read-only, reconnect and disconnect, are shown directly when they fit. Only actual height overflow reveals the “more” button and moves the controls that cannot fit into its popover. Growing the viewer moves them back and hides both the button and open menu, preserving state and callbacks. The rail indicator provides connection status on hover; overflow menus also show details, and failures produce transient feedback. Keyboard and more popovers are mutually exclusive, dismissed outside or with Escape, and never reduce desktop height.

Keyboard controls follow noVNC's extra-key model: Ctrl/Alt/Shift/Win buttons toggle held modifiers, Esc/Tab/Ctrl-Alt-Del send directly, and additional navigation, A-Z, digits and F1-F12 are collapsed. Virtual modifiers work with subsequent physical canvas typing. Direct key presses are paired; modifiers release when toggled off, before read-only/disconnect/reconnect, and on window blur, hidden document or page teardown. The keyboard icon indicates held modifiers while the popover is closed. Uses only pinned public sendKey/sendCtrlAltDel APIs; upstream remains unmodified.

Clipboard has exactly two icon actions and transient feedback, with no text field or panel. RFB events update an internal text cache. Explicit paste reads OS text and submits it to RFB; copy writes the latest cache to the OS. Both buttons call the native clipboard through a private Origin-checked bounded POST. Browser clipboard APIs are never touched, avoiding WebView paste confirmation UI. Full screen has its own fixed toggle endpoint. Neither accepts window/host/target selection or exposes Go RPC. Native callbacks are scoped to live unlocked runs on the UI thread and cancelled on close. No automatic OS clipboard reads/writes. Limit: 64 KiB UTF-8, no NUL. Classic Latin-1 rejects non-Latin-1 until pinned noVNC 1.7 Unicode/Notify capability is negotiated. Read-only, disconnect and reconnect invalidate pending reads and clear the cache; newer remote content wins over a late OS read. Paste feedback means submitted to RFB, not acknowledged by the remote application.

Unmodified upstream/pako sources and hashes are in web/novnc/ORIGIN.json. No new dependencies, CDN, websockify or bundler. tools check verifies source integrity. Opt-in browser_integration runs real RFB authentication, frames, keys, clipboard and credential saves with a private headless browser. Native clipboard callbacks use synthetic storage and browser clipboard APIs are poisoned before loading; tests never touch personal clipboard data. See docs/DEVELOPMENT.md for tasks and docs/VERIFICATION.md for native platform limits.
