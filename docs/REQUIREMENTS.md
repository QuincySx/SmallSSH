## 最新已确认的决定

用户已逐项补充，以下不再作为“是否需要”的候选反复询问：

- UI 优先改得更好看，终端外观与服务器菜单参考 SSHyard，同时保留现有多服务器文件浏览和文件数反馈。
- 主窗口采用用户补充的 Alva 截图结构：连接标签整合到窗口最顶部，左侧保留窗口控制与常用操作，右上角独立设置按钮；去掉底部状态条和常驻“工作台 / 授权中心 / 设置”导航，工作台偏好与授权中心入口收进设置，文件数统计继续保留。
- 重复入口与信息要合并：搜索和新增服务器保留在侧栏，去掉顶栏的重复按钮；新建连接使用紧凑居中 Dialog；公钥引导、独立文件窗各只保留一处标题与来源。设置外边距和内容内边距进一步缩小。
- 中间内容区必须有真实可见的圆角；工作区上下左右及面板之间统一8px可见间距，包含窗口顶部到Tab、Tab到底下终端、终端到底下文件面板，未来左侧面板也使用同值。右上角使用无常驻白底的统一线性设置图标，旁边提供右侧 / 底部工具面板两个入口。只调整呈现与入口，保留已有工具面板的停靠、收起、独立窗口、焦点和窄窗回退业务逻辑。
- 按钮应选用成熟体系，避免继续堆手写图标和临时按钮样式；本轮选用Radix Themes按钮视觉规范与Lucide SVG，由现有MyGo原生按钮承载交互 / 无障碍，先在离线原型评审，不把React组件库说成已直接接入。
- 设置、服务器安装登录公钥与单文件编辑采用独立窗口，窗口均有关闭入口；编辑窗用保存 / 关闭两个图标，底部显示行数、光标位置、编码、换行和大小。Dialog与独立窗口复用公共呈现外壳，业务自行决定保存、取消及未保存关闭保护。
- 文件管理既能停靠在底部 / 右侧，也能成为工作区内占满内容的独立文件管理标签；这与单文件编辑窗、独立工具窗口不同。文件树、导航、上传下载、多来源、多窗、命令、服务器状态和全局传输等已有能力必须保留入口，不能随视觉改版删掉。
- 文件来源 / 路径与目录树、上一级、刷新、新建目录、上传、下载、更多动作合并在同一行，动作靠右，不另占一条工具行；更多文件操作是锚定按钮的临时弹层，不是常驻右侧第三栏，关闭不改变原分栏尺寸。
- 状态页应直接核对并复用现有完整渲染组件，不能用几行占位内容代替已实现的概览 / 进程 / 自启服务 / 系统信息 / Docker。Token只统一视觉；迁移仍需核对内容、入口、状态和交互，不能宣称改Token就自动补齐功能。
- 单文件双击默认打开独立原生窗口，在该窗口内立即反馈加载；连接、下载也要有可见的窗口式进度反馈。
- 完整变量体系必须做；配置导入 / 导出、常见 SSH 客户端迁移必须做。
- 不另建复杂快连页；普通连接表单允许名称留空，填目标地址、用户名及认证资料后直接连接，名称自动生成。
- 密钥按服务器登录身份分别生成，不做全局共享密钥管理页面；公钥部署与硬件密钥都需要 onboarding。
- 加密本地备份 / 恢复、目录上传、tmux 会话列表与快速切换、串口连接必须做。
- 终端搜索、选中即复制、远端 OSC 52、自动重连与保活均应有清楚入口和设置；它们是不同能力。
- 每次双击服务器都打开一个新的终端，保留已有实现，不能改回复用唯一终端。

“内置 AI / ACP 是否进入首版”、跨服务器直接复制、硬件型号与 UDP 旧协议兼容等尚未由这段说明完全确定，继续保留待定，不能据截图自行替用户全选。

## 怎样算做完

| 记录 | 实际含义 | 可以算产品功能完成吗 |
|---|---|---|
| 需求已记录 / 方案已写 | 知道要做什么、准备怎样做 | 不可以 |
| 改了字符串或说明 | 按钮、字段、提示或文档变了 | 只算文案工作；除非需求本身就是文案，不算能力实现 |
| 代码已实现 | 产品入口与实际执行路径已经接通 | 仍需验证 |
| 自动验收通过 | 有对应行为测试、离线 UI 或协议夹具证据 | 仅证明所测范围 |
| 待实机验收 | 还需用户的服务器、硬件或原生窗口确认 | 不得写成全面兼容 |
| 用户确认交付 | 功能、入口、行为与预期一致，已解决已知阻塞 | 才关闭对应需求 |
| 已打包 / 已安装 | 当前代码进入安装包 | 不代表所有需求已经完成 |

当前安装包版本仍为 0.0.1。已有多项功能和自动验收，但完整 0.1 尚未交付。窗口视觉已迁入正式产品代码，命令确认开关与 Linux 端口列表也已接入；打包 / 安装和测试证据见 VERIFICATION.md。完整0.1其余功能缺口继续保留。

### B 包含哪些后台任务

U04 也包含原 B06 计划中的后台单文件下载：必须明确交给宿主、固定服务器和路径范围，GUI 退出后才可按批准条款继续。锁定、撤权或到期停止，后台重启不能恢复已失效授权；不能把 GUI 签名器保存为后台任务身份。普通终端和所有客户端任务并不因此自动变成永久后台任务。该闭环目前未实现。

### 变量需求的具体例子（设计默认，可由用户调整）

用户要的是“值随环境变”，并不只是在 Debian / RedHat 下保存两份整段命令。

例如一份模板 `systemctl status {{ssh_service}}`：服务器 A 的 `ssh_service=ssh`，服务器 B 的 `ssh_service=sshd`。运行时显示本次用了哪个值和完整命令；临时修改不悄悄改掉保存值。`{{...}}` 只是拟议语法，当前产品未实现。

按完整变量需求设计为 **公共默认 → 环境 / 分组 → 服务器 → 本次输入**，越靠右越优先。此为主代理提出的设计默认，不冒充用户逐条确认；用户可调整。参数历史保持独立，不把上次输入自动当作环境配置。秘密值不通过普通变量隐式导出给外部 Agent。

### UDP 加速需要真正交付什么

U09 的完成条件至少包含：本机加速端、远端配套端、有序可靠传输、对端认证、SSH / SFTP 实际接入、连接配置、失败 / 取消 / 停用反馈，以及延迟 / 丢包 / 吞吐对照结果。仍保持 SSH 目标指纹与授权校验，不承诺任意网络都更快。

“智能”模式还要明确何时测速、依据什么选择、何时回退及是否需要用户确认；当前手动比较一次建连耗时不满足该定义。

第一版对端放在“自有目标服务器”还是“独立中转服务器”，需在技术验证时确定；当前按同类能力规划，不预设旧 FinalSpeed 协议兼容。这里只确定产品形态，不代表已授权部署到任何服务器或修改防火墙。

|---|---|

| 收藏 / 移动到分组 | 改变连接组织方式，保留正在运行的终端与实际目标 |

| 新建端口转发 | 复用现有三类隧道能力，解释方向、监听与目标，默认只监听回环地址 |

普通连接只要求有明确目标地址、用户名与相应认证资料，名称可空并自动生成。不额外造一个复杂的快连产品页；密码、密钥、自动、SSH agent、硬件分别可选，未用到的字段收起。

“自动”是按本服务器允许的已绑定身份选择，不是自动接受服务器指纹，也不是试遍所有服务器的密码 / 私钥；需要触摸、PIN 或人工输入时仍明确提示。

端口转发的用户解释：

| 类型 | 用途举例 |
|---|---|
| 本地转发 | 本机 127.0.0.1:15432 经 SSH 访问服务器内网的数据库端口 |
| 远程转发 | 远端回环监听端口经 SSH 访问本机开发服务 |
| 动态转发 | 本机提供 SOCKS 入口，选定应用通过该 SSH 服务器访问网络 |

三者依托 SSH 连接转发，U09 另行提供 UDP 加速传输能力。

### 服务器专属密钥与 onboarding

不做让用户把一把密钥到处复用的全局管理页面。入口位于每台服务器的“安全与密钥”，后台仍统一保管秘密和审计。

流程：当前方式登录 → 为此服务器登录身份生成软件密钥或选择硬件身份 → 核对服务器 / 账号 / 公钥指纹 → 追加安装公钥 → 新建仅用该身份的连接验证 → 验证成功后由用户确认切换。原登录方式在验证前保留。

- 新生成的软件密钥使用独立随机密钥对，默认不跨服务器登录身份复用。显示名称、分组或模板克隆不复制这种绑定。
- 硬件私钥留在设备，应用取得公开身份并请求签名。已有硬件身份的接入与“在设备上新生成密钥”是两个步骤；设备槽位、算法与 FIDO / PIV 能力先检测，不能承诺无限服务器独立密钥或覆盖已有槽位。
- 部署端处理目标账号的 SSH 公钥授权位置与权限，保留已有条目，识别重复项。先支持并验证明确的服务端类型，不能把所有服务器都当同一种 Unix 路径。
- 仅“写入成功”不算登录成功。独立验证仍检查原服务器主机身份及登录账号；部分成功或连接中断时显示真实阶段，不自动重放未知写操作。
- 导入旧配置可能带来原本共享的密钥：先如实显示重复指纹，再提供逐服务器更换引导，不静默破坏已有登录。

公开资料边界：[OpenSSH 的认证密钥说明](https://man.openbsd.org/ssh-keygen)与[服务端授权公钥格式](https://man.openbsd.org/sshd#AUTHORIZED_KEYS_FILE_FORMAT)用于核对接入；[Yubico PIV 槽位说明](https://docs.yubico.com/yesdk/users-manual/application-piv/slots.html)表明设备资源有限。这里没有进行真实设备初始化、生成密钥或服务器部署。

### 文件窗口、传输与设置

文件工作窗绑定服务器身份与路径，先创建窗口再后台读取；切换工作台服务器不改变其来源。加载、取消、重试、只读 / 不支持、保存冲突和未保存关闭都在该窗口表达。默认独立窗口，设置可提供标签模式；同一文件重复打开时建议聚焦原窗，主动“另开副本”另列操作，避免无提示地并发覆盖。

常见配置、脚本、日志和无扩展文本按内容可读性与类型处理，不只靠扩展名。编码、换行和大小有明确提示，保存不悄悄改变格式；图片 / PDF / 二进制不强行当文本编辑，后续预览类型单列。

大日志需区分分段只读预览与全量编辑，不能仅把读取上限调大后占满内存；询问继续打开也不等于取消最大编辑限制。

文件设置至少分开表达：

| 设置 | 含义 |
|---|---|
| 同时传输数量 | 控制实际执行中的传输，不等于可打开文件窗数量；建议全局上限，避免每个面板各自扩出同样数量 |
| 大于多大先询问 | 打开前提示是否继续，不是直接读取上限 |
| 最大可打开大小 | 防止无限占用内存，与上条分开显示 |
| 文件管理面板位置 | 右侧 / 底部，保留多服务器来源选择 |
| 单文件打开方式 | 默认独立窗口，可选工作台标签 |

目录上传、下载共用队列 / 进度 / 暂停恢复；统计当前目录文件数、文件夹数与已选数，不以一个模糊总数代替。下载与连接由明确窗口反馈，后台进度更新不反复抢焦点。

### 变量体系

把变量定义、作用域、类型、默认值、来源与本次覆盖统一解析，命令运行面板显示“本次取了哪一层的值”和最终命令。位置参数与历史保留，但不能代替环境配置。解析失败不发送半成品命令；临时值不悄悄写回持久配置。作用域按前述设计默认处理；未定义、循环引用与类型错误有明确反馈，预览期间不执行 shell 表达式或加载脚本。

发送绑定最终展开文本、目标和变量快照；预览后目标或取值改变必须更新预览与相关授权，不能校验模板后执行另一份展开结果。

### 导入 / 导出与本地加密备份

迁移统一为“选择来源 → 预览可导入内容和诊断 → 处理重复 / 分组 / 无法解密项 → 保存后验证”。先做 SSH config，再按常见客户端的真实格式分批实现；不把能读文件等同于能恢复所有旧版密码库。

普通配置导出默认不含密码、私钥或 PIN。完整迁移使用密码加密本地备份，备份在安全核心内加密后再交给文件保存流程；恢复前显示内容及冲突，不恢复活会话、票据或本机设备授权。硬件私钥不能被软件备份，恢复后需重新发现 / 绑定设备。云目标与定时备份本轮未自动加入。

### tmux、串口、剪贴板与连接恢复

- tmux：先检测服务端是否已有 tmux，列出现存会话 / 窗口 / 活动状态，提供附着与切换。不自动安装软件；当前终端忙时不直接往正在运行的程序里塞 attach 命令，可新建终端附着。
- 串口：作为本机设备连接，配置设备、波特率、数据位、校验、停止位和流控；提供连接、断开、重连与 Break。复用终端显示 / 搜索 / 外观，但不伪装成需要 SSH 密码的服务器登录。
- 搜索：把已有终端底层 Search / Next / Previous 接到搜索栏和快捷键，终端回滚内容也可查找。
- 剪贴板：选中复制与 OSC 52 分开；远端写本机剪贴板和远端读本机剪贴板也分开。建议远端写入可关闭 / 询问 / 仅当前连接允许，读取默认拒绝；明确来源与大小限制。
- 保活：定时探测仍然存在的连接，帮助维持空闲链路并发现死连接，不提供吞吐加速。
- 自动重连：断开后按配置间隔 / 次数重新建连并认证，可停止；不恢复失效的外部授权，不重放命令。tmux 的用途是找回服务端仍存活的工作，它与重连 / 保活是三件事。

### UDP 加速

实际数据路径应为：应用的 SSH / SFTP → 本机可靠 UDP 传输 → 远端加速对端 → 目标 SSH 服务。SSH 继续端到端核对主机身份，加速对端有自己的认证与授权，不能变成任意目标的开放代理。

先交付可运行的两端最小验证及丢包 / 延迟 / 吞吐对照，再接入连接配置和真实 SSH / SFTP。用户尚未提出已有 FinalSpeed 服务端需要对接，设计默认是实现同类可靠 UDP 加速能力，不预设旧协议兼容；若后续明确有旧端点，则单列兼容需求。协议实现仍需基准与维护性核对后选定。这里是实现方案，没有现成 UDP 功能落地，不能只添加一个“智能加速”开关。
