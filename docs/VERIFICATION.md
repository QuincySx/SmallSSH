## 桌面实际操作

在单独测试目录、临时生成的本地 SSH 服务上，用用户提供的测试主密码 `123123` 完成：

1. 解锁、打开独立授权弹窗、批准终端连接；Ghostty 输入与远端回显可见。
2. 浏览远程目录，读取 UTF-8 测试文本，修改并批准覆盖保存。
3. 文件系统复核新内容正确，独立旧副本保留原内容。
4. CLI 申请上传，桌面弹窗核对目标路径和内容 SHA256 后批准；CLI 下载再经桌面批准，往返内容完全一致。
5. 错误密码无法批准；输入正确测试密码拒绝操作后，等待中的 CLI 返回拒绝。
6. 在真实控制终端中输入测试主密码批准 CLI 请求，调用方收到测试命令结果。
7. 立即锁定后，连接和界面中的文件内容被清除。
8. 密码框辅助功能缓存修复后，通过 AX 填入测试密码再读取，接口不返回明文；点击解锁仍正常。

第二轮实际桌面操作：

1. 在分组树将连接从「开发测试」移入「个人服务器」，重启后保留，原密码仍可打开终端。
2. 验收左侧分组搜索、可拖动分栏、上方终端标签和下方文件/传输面板。
3. 在安全设置中检测并启用 macOS Secure Enclave / 系统验证；锁定后通过系统验证成功解锁。另一次在验证等待时点取消，保险库仍锁定。
4. CLI 创建下载，桌面队列可见；桌面点暂停使 CLI 返回取消，旧授权被撤回；桌面继续时生成新的授权 ID。

# 客户端会话与一次性子授权 · 2026-10-21

## 多终端共享服务器采集与状态缓存 · 2026-10-23

原实现只在执行层共用限速，仍为每个终端建立三套采样循环。现在 broker 为同一保存连接 ID、SSH 用户、实际连接地址及已核对主机指纹维护一个采集器；固定一个基础计数、一个系统清单和一个 Docker 资源循环，保留单一 previous / latest，终端和公开 monitor 订阅同一份不可变结果。不同保存连接条目与账号不共享结果，仍共用全局地址采样预算，避免凭据权限不同的配置之间泄漏状态。

每个采集器发出独立生命周期的 SourceID，慢订阅者只保留最新一个事件，不阻塞采集和其他订阅。采集复用仍获授权的现有 SSH 连接，不额外 Dial；提供连接关闭或被撤销后由其他获授权连接接替。最后一个存活订阅结束就停止采集；异步清理未完成时重新订阅也会创建新 SourceID / 空缓存，旧清理不能删除新对象。Server.Close 等待探测与真实异步清理结束。常规完成后间隔保持基础 2 秒、Docker 10 秒、系统清单 60 秒；已开始且被撤销的探测保留 2 秒冷却，避免一分钟接替停顿及反复取消绕过限额。尚未取得执行槽的取消不修改已有预算。

桌面按 broker SourceID 保留一份 canonical stats 与最多 451 个趋势点；相同时间戳不重复追加，旧回包不覆盖新状态。各终端共享 stats 指针和 history backing。断开的标签只复制一次冻结历史，不受后续压缩更新影响；最后一个 live 引用离开、替换或锁定时释放活动缓存。无 SourceID 的旧 / 合成消息保留原本的会话隔离。进程、服务和 Compose 操作仍绑定发起的具体会话；操作后清单在同源标签共享，过期自动清单不能覆盖新结果。

## 自动验证门控改用后端激活状态、原生视图只在 anchor 变化时追帧 · 2026-10-27

## 服务器状态只在显示时采集，多条终端共用一个采集器 · 2026-10-27

所有者提出的性能问题：底下工具面板的文件 / Docker / 服务器状态都要向服务器取数据，应当"不显示就不拿"，而且多条终端连同一台服务器时只留一份采集。核查后分两种情况：

- **同一台服务器只取一次：原来就已经是共享的**。`internal/broker/monitor_shared.go` 按 `monitorTarget`（保存连接 + SSH 用户 + 实际地址 + 已核对指纹）复用 `monitorCollector`，订阅者共享同一份计数器 / Docker / 清单结果；只有最后一个订阅者离开才停止。既有测试 `TestSharedMonitorFanoutCacheProviderHandoffAndCleanup`、`TestSharedMonitorSlowDockerDoesNotMultiplyWork` 已覆盖，本轮未改这部分语义。
- **"不显示就不拿"原来没有**：采集在终端会话建立时就启动，面板收起、切到别的工具页或换到别的标签都照旧每 2 秒执行一次远端命令。现在补上：会话通过 `{"action":"monitor","monitorActive":bool}` 报告自己是否仍在显示状态，collector 只有存在 active 订阅者时才探测；全部暂停时三个采集循环（计数器 2 秒、Docker 10 秒、清单 60 秒）一起挂起，恢复时立即给出一份新样本，同时先回放缓存样本避免面板空白。暂停不会关闭会话或 SSH 传输，所以恢复不需要重连。
- 可见性判定在桌面侧：工作台页 + 工具面板展开 + 当前工具页是「服务器状态」+ 该终端是当前终端；主窗口隐藏时暂停，工具面板独立成窗时以独立窗口为准（`serverStateSession`）。判定集中在 `monitorWanted`，每个渲染帧末尾 `syncMonitorVisibility` 只对状态发生变化的会话发消息，窗口显示 / 隐藏事件也会触发一次。

文件区本来就不做周期性读取：只在进入目录、切换目标、手动刷新 / F5 时读取一次，面板切换不会重新拉取，因此本轮没有改动。

验证：

- `go test ./internal/broker -run 'TestSharedMonitor'` 全部通过；新增 `TestSharedMonitorProbesPauseWhileNothingShowsThem`（全部暂停后 2 秒内远端命令次数不再增长，恢复后继续）与 `TestSharedMonitorKeepsProbingWhileAnotherSubscriberShowsIt`（一个隐藏、一个显示时仍采样）。
- 新增 `TestMonitorVisibilityFollowsTheStatusPanel` 覆盖面板展开、其它工具页、其它页面、未登录、无会话五种情形。
- `go run ./tools check` 通过（日志 `build/logs/check-20261027-*.log`）。

未做：没有实机观察暂停后服务器负载与 UI 恢复速度；Docker 页独立于状态概览的暂停粒度（当前与状态面板同进退）未单独区分。

## Publisher 一次打出全部平台 · 2026-10-27

此前手动工作流的默认输入只有 `darwin/arm64`，等于每次发版要点一次名字还只出一个平台。改正：

- `tools build` 新增 `-platform all`，展开为本项目发布的五个桌面目标：`darwin/arm64`、`darwin/amd64`、`linux/amd64`、`linux/arm64`、`windows/amd64`。`Publisher` 的默认输入就是 `all`，仍可手动填单个目标。发布清单只在这一个常量里，工作流不重复写目标列表。
- `Cross build` 的 PR 编译矩阵同步补齐到这五个目标，不再漏掉 darwin/amd64 与 linux/arm64。
- 打包收集从 `build/*/` 改为 `build/*-amd64/`、`build/*-arm64/`，避免把遗留的 `linux-qa`、`native-downloads` 之类的目录也打进 artifact。
- 本机用 `-platform all` 完整打包一次验证：84 秒产出两个 `.app`、linux amd64/arm64 的 deb 与 tar.gz、windows exe，五个目录各自打 tar。
- x86_64 原生组件的哈希随本轮重建更新（`internal/systemauth/native-hashes.json` 的 darwin/amd64 两项），因为签名产物随 Xcode 版本变化；`go run ./tools build -check -platform all` 现在报告生成文件均为最新。这也再次说明为什么打包不能放进自动检查。

未做：`Publisher` 仍只在手动点击时运行，本轮也没有在 GitHub 上真正触发过；多平台打包只在本机验证。
