# 安全与边界

## 所有者与受托客户端 · 2026-10-24

完整职责和验收基准见 [网关内核、管理端与调用方](ARCHITECTURE.md#网关内核管理端与调用方--2026-10-22)。以下区分已实现的服务器策略与仍存在的隔离边界。

- 桌面是默认完整管理客户端，权限来自已验证的所有者会话，不来自“桌面”标签。人类 CLI 经所有者验证可承担无桌面管理；AI / 自动化 CLI 持有受托身份，只能使用获准能力和查看自身结果。
- 策略、全局授权队列、全局审计查询 / 导出 / 清理由所有者管理；调用方可以申请、查询和撤回自己的任务与授权，不能自批、扩权、修改服务器或管理审计记录。名称、公钥持有证明与已验证软件品牌是不同概念。
- 连接的“AI 访问”可关闭全部受托 AI / CLI 访问。代理在创建审批和目标网络访问前拒绝并持久记录，不创建弹窗；仅修改自动化策略会使该连接的受托授权及 AI 通道失效，保留正在使用的所有者人工终端；目标、指纹或凭据变更仍撤销全部旧授权。所有者签名操作仍可使用；自报“桌面”或“所有者”不能获得豁免。
- 长授权不取消操作检查；任意 Shell 的路径安全需要服务器权限或受控执行边界，不能以拦截 `rm` 或本地路径前缀匹配声称强保护。SSH 断开不能证明远端任务已终止，结果未知时不能自动重放写操作。
- `hosts/pending` 和主机探测、SSH 代理身份枚举只接受一次性所有者查询证明；证明绑定动作、目标、端口和分页。`status/sessionStatus` 接受同样的所有者证明，或只允许票据持有者读取该票据对应的请求。委托挑战与续期挑战也要求父票据；签发操作仍另外核验客户端签名。桌面使用已解锁会话签名，外部调用方不能根据名称取得管理读取权限。IPC 与会话文件仍按 OS 用户隔离，不能抵抗同用户恶意程序读取别人的能力文件。
- 授权中心“历史”读取持久 `audit.jsonl`，记录服务器、申请方、操作类型、授权生命周期及拒绝原因。查询 RPC 需要所有者一次性证明，包含分页参数且不可重放；已解锁桌面无需再次输入密码。申请方自报名称明确标记，所有者来源仅依据代理验证的 `OwnerIssued`。Unix 日志为 `0600` 明文元数据，同 OS 用户直接读取无需应用级证明；没有防篡改或完整回放保证。记录保留操作摘录（命令、路径、目标路径各最多 512 字节，容器 / Compose 对象最多 128 字节），因为看不出执行了什么的记录无法审查；口令、私钥、输出与票据不记录。摘录是本机明文，命令里带的秘密会一起落盘。

## 关键路径保护

旧连接和新连接的零值策略均默认启用保护。默认保护系统目录和用户主目录，所有者可编辑保护路径；关闭保护需要明确确认完整权限风险。根目录本身始终不能作为受控修改目标，配置 `/` 则保护全部后代。保护覆盖文件读取、目录内容列举、属性读取、下载、新建、覆盖、非递归删除和重命名的源与目标；修改时同时拒绝移动受保护目录的祖先。读取父目录可见其条目名称，不代表可以列举保护目录或读取其内容。

保护模式拒绝受托方的任意 `exec`、交互 Shell、容器终端和 Compose 更新，而不是解析命令文字判断是否安全。它也拒绝直接改权限 / 属主与续传写入，因为 SFTP 不能证明已有 inode 未通过硬链接关联受保护文件。完整父授权不能覆盖服务器策略。文件读取和下载还须通过保护路径检查；固定状态、日志及计划检查仍按原授权执行。限制文件根目录的会话不开放这些额外的状态、日志和计划能力。

可放行的受控读写还须在 SSH 登录后用 SFTP 核对规范路径，拒绝目标及祖先中的符号链接、受保护根目录别名和解析失败。受托文件属性读取只返回目标元数据，不额外读取 `/etc/passwd` 或 `/etc/group`。受保护根目录的链接目标若含 `..` 直接拒绝。代理自己的写锁从检查保持至提交。远端其他进程仍可能竞争更换目录，bind mount 等别名也无法由 SFTP 完整证明；这不是服务器端文件系统沙箱。需要抵抗独立远端进程时，应同时使用受限 SSH 账号和服务器端权限。

这是开发预览，还未完成独立安全审计。

## 已实现

- 连接资料整体加密；AEAD 认证头部；新 nonce；加密文件原子替换。创建新库不覆盖已有文件。
- 主机身份必须匹配已记录的 SHA256 指纹，认证之前完成核对。首次探测只展示候选指纹，必须另行核实。
- 不提供导出口令、私钥或解锁密码的公开代理接口；SSH 私钥无需落入临时明文文件。
- 本机桌面连接、文件读写及传输使用当前解锁会话的密钥计算具体操作证明；不缓存主密码。外部 CLI / AI 无法借用桌面解锁状态自批；单次请求或客户端会话的批准仍需所有者验证，已批准会话内的子操作按既定范围签发；不提供仅传 `yes` 即可通过的公开接口。
- 授权绑定到一次具体操作；上传和覆盖保存绑定内容摘要。单次随机票据不能重放。外部请求及文件操作最长 15 分钟；带所有者签名的人工终端绑定代理和解锁会话，直到关闭、锁定、撤销或退出。
- 锁定、撤销、到期会取消进行中的连接；配置变更会撤销该服务器的旧请求，其他服务器的授权不受影响。
- Unix 私有目录/套接字权限，Windows 当前用户 SID 的管道 ACL。没有 localhost HTTP 管理端口。
- 带长度上限的本地协议、按操作类型拒绝无关字段、严格 SHA256 / 传输 ID 格式、编码后操作体 64 KiB 上限。授权队列每页至多 8 条，分页参数参与查询证明；客户端逐页汇总。流式文件传输、普通命令每路 8 MiB 输出上限、编辑器 4 MiB UTF-8 文本上限。
- 上传采用无覆盖提交；覆盖保存需要原内容摘要、保留独立旧副本并使用原子重命名。
- 审计日志保留操作摘录（命令、路径、目标路径各最多 512 字节，容器 / Compose 对象最多 128 字节），批准、开始、结束与拒绝都带，事后才能对上“谁在什么时候执行了什么”；口令、私钥、输出与票据不记录。摘录是所有者本机的 `0600` 明文，不要把秘密写进命令。结束记录保存成功 / 失败 / 取消 / 结果未确认及可用的退出码，必须先落盘再回复成功。取消记录表示本地通道被取消，不证明已脱离 SSH 会话的远端进程终止。任何操作审计写入失败都会撤销现有授权并锁存故障；修复存储后须锁定并重新解锁，不在当前代理会话内自行恢复授权。
- 内置自动服务器状态采样与界面轮询不逐次进入操作审计；保留外层授权和会话生命周期。重复采样失败只更新状态并退避。固定内置执行路径不接受任意采样命令；调用方标签、`ServerStatus` 或相同命令文本不能让人工 / AI 请求免审计。策略拒绝、越权子操作、坏授权证明和无效续期会记录拒绝元数据。
- 历史每页最多100条，桌面每页50条；单文件8 MiB并保留一个归档。读取限额包括行长、损坏行扫描数和元数据长度；轮转后过期游标要求重新加载。只有历史页可见时才按至少3秒间隔读取，分页旧页不自动刷新；锁定清除界面缓存。
- vendored MyGo 的 macOS 密码字段在辅助功能 setter 注入后不再缓存可读明文；getter 和旧 AXValue 接口也进行隐藏。补丁见 `patches/`。

## 不应作出的保证

**同一个操作系统账户内的恶意进程不是强隔离沙箱。** 本地文件权限可阻止其他普通账户访问，HMAC 可阻止不知道主密码的调用方直接自批；但不能保证抵抗同用户调试器、注入、键盘记录、替换客户端或管理员/root。AI 若持有无限制的同用户 shell，也属于这一限制。后续需要签名、验证本地进程身份、受保护的系统密钥和更强的进程隔离。

申请方名称是自报标签，目前未验证进程签名。不要把显示为“用户”或某个 AI 名称当作可信身份。

允许 `exec` 或完整终端就允许该 SSH 账户权限范围内的行为。程序不靠命令字符串猜测其是否“只读”，也不把命令审批称作服务器沙箱。

Go 的字符串、SSH 库和垃圾回收可能保留密钥与口令副本；清除字段和主动覆盖字节切片不等于可证明的全内存擦除。当前没有 swap、休眠文件或崩溃转储的强制保护。

系统认证不保存主密码，公开代理协议也不能取出保险库密钥：

- macOS：Secure Enclave P-256 私钥带 `userPresence` 访问控制，ECDH、HKDF 与 AES-GCM 包装保险库密钥。私钥使用时提供新 LAContext，认证复用时间为 0。允许 Touch ID 或系统登录凭据策略，不能声称仅限指纹。helper 从 JSON stdin 接收请求，校验固定 SHA256，不从命令参数或环境变量接收密钥。
- Windows：桌面 WinRT interop 请求 Windows Hello，验证通过后才调用当前用户 DPAPI 解密。取消、失败、没有可用窗口均拒绝。DPAPI 本身没有绑定每次 Hello 的硬件不可导出保证；同用户恶意程序可能绕过本应用的门禁调用 DPAPI。
- Linux：fprintd 已登记指纹验证成功后才读取 Secret Service 中的包装密钥。核对系统总线上 fprintd 的唯一发送者、指定设备和接口。需要已登记指纹、fprintd、secret-tool 和可用钥匙串。普通 Secret Service 并不从密码学上强制每次取密钥都验指纹，同用户恶意程序可绕过本应用的门禁。

不能把三种后端都称为 Secure Enclave。实际硬件验收范围见验收记录。

SFTP 没有原子的内容比较交换。覆盖保存能检测已发生的内容变化并保留独立旧副本，但外部进程仍可在最终核对与提交之间竞争。新文件的扩展属性、ACL 和原属主不会被完整保留。正在被其他程序持续写入的文件应另行协调。

远程上传需要 `hardlink@openssh.com`，覆盖保存需要 `posix-rename@openssh.com`；缺少扩展时明确报错。命令取消会关闭 SSH 会话，但远程程序主动脱离会话后不能保证被杀死。

主密码轮换、库备份恢复、FIDO 硬件令牌、多因素 SSH 交互登录和防篡改审计尚未完成。未核实 Windows/Linux 桌面实机行为，不能仅凭交叉编译宣称三平台安全验证完成。

## 续传与监控

新建上传使用 `put` 并绑定传输 ID、大小和摘要，服务端以 `O_EXCL` 创建部分文件，任何已有部分 inode（包括零长度硬链接）均不复用。目标或部分文件已存在时要求新建任务；不会把新建失败自动降级为续传。确实已发送数据的重试才申请 `put-resume`，保护模式继续拒绝该能力。所有者人工传输保留既有续传通道。

续传绑定服务器、路径、传输 ID、大小、完整摘要和已知前缀摘要。上传先比对远端部分文件前缀，完成后校验全文件；下载绑定首次取得的远端完整摘要，恢复时比对本地前缀与远端摘要。最终目标无覆盖提交，部分文件在暂停后保留。任务锁阻止同一任务被两个进程同时执行；恢复不复用之前的授权。

可选会话 `readRoot/writeRoot` 将文件能力进一步限定到规范绝对目录。只要设置任一根目录，空的另一项表示不开放对应文件能力；不开放任意命令、终端、属性修改、续传写入、监控、容器日志或 Compose。根目录参与所有者证明、子授权检查、远端路径检查和续期一致性检查。此限制约束路径条目，无法证明硬链接或挂载别名的原始来源，抵抗恶意远端进程仍需服务器端权限或隔离。

任务元数据含路径，按当前用户私有目录保护，不是加密保险库的一部分。进度可能比实际部分文件晚一秒，恢复以重新检查的文件为准。校验采用流式处理，完整扫描会增加大文件初次传输和恢复的等待时间。

监控只运行内置 Linux 采样命令，不接受自定义命令，使用相同授权和撤销机制。网络统计汇总非 loopback 接口，在网桥 / VPN 场景可能重复计数；进程 CPU 由 ps 报告，系统 CPU 使用两次采样的差值。需要 Linux /proc、df 和 procps 兼容的 ps。

桌面终端在同一请求中明确申请 `shell` 与 `serverStatus: true`，授权说明展示“终端连接＋自动读取服务器状态”。此字段参与不可变请求签名，只能与无自定义命令的终端请求组合。状态使用同一个已授权 SSH 连接中的独立通道，不派生额外授权、不重复登录；固定命令的读取超时、失败或不支持状态接口不会使终端退出。关闭终端、到期、锁定或撤销同一授权时同时停止。CLI 的普通 `shell` 与单独 `monitor` 请求保留原来的范围。

## 连接创建与编辑

读取候选主机身份在 SSH 密钥交换回调中中止，不进入用户认证。探测到的指纹仍须用户通过可信渠道核对，不自动信任。连接表单把确认绑定到具体地址和端口，改变目标会清除确认；真正登录仍由代理强制核验已保存指纹。

身份不一致时在认证前拒绝连接；重新核对入口只清除当前表单中的信任，再次探测和明确确认后才提交新记录。不会因连接失败自动覆盖旧指纹。

编辑连接的凭据保留 / 替换选择、全部提交字段与一次性配置挑战一起纳入所有者证明。保留模式不把已有口令或私钥返回界面。私钥在导入检查和提交时解析，公钥文件、错误口令及无效格式会拒绝，错误消息不包含原始材料。

私钥选择结果和直接输入的路径都通过同一受限读取及解析流程；检查前拒绝非普通文件和超大文件。保存的是保险库内的加密副本，不依赖原文件继续存在，也不删除或改写用户原文件。文件选择器等待在渲染回调外进行，迟到的选择结果不能恢复已取消的表单。

“保存并连接”展示目标、终端及固定只读状态范围。首次指纹确认使用独立页面和明确的「信任并连接 / 保存」按钮，没有隐藏在表单中的勾选框。保存、普通双击终端、文件操作及传输使用桌面进程已有的已解锁 `vault.Session`，经同一代理计算和核验精确绑定的挑战 / 请求证明；不再次解密保险库、不缓存主密码、不提供无需所有者证明的公开授权接口。该会话由主密码或系统验证建立，锁定或退出时关闭并清除密钥。不会批准其他排队的 CLI 或 AI 请求，调用方自报标签不会获得桌面权限。保存已经完成时取消后续连接，会保留已保存配置并在界面区分两步结果。

## 开发窗口控制

后台开发模式在独立数据目录运行；主窗口和授权弹窗在明确显示前保持隐藏。开发窗口的私有本地控制仅支持 `status / show / quit`，不提供解锁、SSH 执行、凭据读取或批准请求操作；显示窗口仍需正常解锁；外部请求沿用独立的所有者批准或已批准客户端会话。控制仅在后台模式启用，普通启动不监听这个接口。

传输复用当前用户私有目录 / Unix 套接字及 Windows SID 限制管道，没有 TCP 监听端口。输入按既有协议限制大小和超时，无效操作在调用界面处理器前拒绝；退出前先返回响应，再走正常会话清理。它不构成同一操作系统账户中恶意进程的强隔离边界，限制与上文一致。


## 本机所有者操作与外部请求的隔离

桌面不是根据申请方标签自批。它先取得一次性管理挑战，用内存中已解锁会话对完整操作、用途域与挑战 ID 计算 HMAC，再通过 `ownerRequest` 验证。代理自行填入当前服务器端点和已信任指纹，签发包含 `ownerIssued` 的不可变请求；桌面再为该精确请求计算批准证明，仍经相同的审计与一次性票据启动路径。标记由代理验证后设置，公开 `request` 中注入同名字段或伪称桌面均无效。

只有签名创建的本机 `shell` 请求带 `ownerSession`，运行上下文随代理会话结束；未启动的请求仍有 15 分钟期限。外部 CLI / AI 的终端及所有文件任务保留原有限期；普通请求不能通过自报来源获得持续会话。两项标记都参与批准证明并写入审计元数据。变更操作、重放挑战、替换标记或未签名创建均有拒绝测试。

用户明确确认的拒绝与撤销可使用已解锁会话，减少权限不需要再次输入密码。外部请求的允许仍要求新主密码验证或本次系统验证；系统验证即使在取消后迟到返回成功，也不能释放密钥或提交启用记录。

锁定先取消操作上下文并关闭内存密钥，再进行网络清理；后台完成回调按会话世代检查，旧结果不能写回新解锁状态。SSH 代理签名阶段保持握手超时与取消处理。读取本地文本前检查普通文件、大小、打开后的文件身份，覆盖前重新检查内容；远程下载拒绝目录和非普通文件。授权展示转义控制字符与不可见方向字符，折叠详情只改变展示，不改变签名内容。

空闲与身份：解锁后代理持有所有者能力，因此键盘与鼠标静置 15 分钟后保险库自动锁定（同时要求"系统空闲时长"与"本次解锁已持续时长"都达标，避免在长时间离开后刚解锁就立刻自锁）。本地套接字在 accept 时向内核核对对端 UID（macOS `LOCAL_PEERCRED`、Linux `SO_PEERCRED`，Windows 沿用限定当前 SID 的 DACL），不是当前用户就直接关闭，不读取任何一帧；目录 0700 与 socket 0600 仍然保留。

审计链：每条记录写入时带上一条记录的 SHA256（`prev`）。打开历史时校验归档文件再到当前文件，发现某条记录被编辑或删除即拒绝启动代理，而不是写入一份无法证实的日志。旧版本写入的无链记录按"遗留前缀"接受，下一条记录从它继续链接。任何能完整重写整份日志的本地同用户进程仍无法被链本身发现——链提供的是"改中间会被发现"，不是"改全部不能发生"。

脱敏发现：`hosts` 在没有所有者证明时只返回连接 ID、分组与名称。这是刻意让自动化获得"申请对象"的能力，代价是同一用户下的本地进程也能看到这些名称；地址、账号、指纹与策略不返回。

续期与队列：调用方的待处理配额按**内核报告的对端进程**计（macOS `LOCAL_PEERPID`、Linux `SO_PEERCRED` 的 pid），不是按请求里自报的标签——换标签不能换来新的配额。同一个进程十六个槽位，另一个进程另有自己的十六个。客户端会话每次续期都会累加计数，审批界面与审计记录都写明"连续第 N 次"，让不断延长的授权在评审和事后追溯中都可见。同一申请方的待处理请求有独立上限（16 条），避免一个调用方灌满队列把别人的申请挤出所有者的视野；全局上限仍是 128 条，已结束的记录不会阻塞正常浏览。

审计锚点：代理每次正常关闭（以及桌面每次锁定，在丢弃签名密钥之前）把审计链头写进**加密的保险库**（`auditHead`）。解锁时要求保留的历史里**仍然找得到**这条记录，找不到即拒绝启动，因为"整份日志重写"可以自造一条自洽的链，却造不出保险库里那一份，重写保险库需要主密码。锚点承诺的是历史的一个前缀而不是最后一行：崩溃、强杀、或锁定后无法再写保险库留下的"未提交尾段"会被接受，不会把人锁在门外；代价是锚点之后的追加无法检测（追加本来就没有外部承诺）。审计按 8 MiB 轮转，两次轮转把锚点记录挤掉后同样会被拒绝，需要从备份恢复审计历史。删除锚点表现为"首次运行"，与真正的首次运行不可区分——所以它防的是"改动而不留痕"，不是"删库"。

连接复用：短操作（列目录、文件属性、执行命令、重命名等）会把**已校验过的 SSH 连接**留给下一次操作，省掉每次 100–300 ms 的握手；终端和流式操作各自独占，失败的操作关闭自己的连接，不把可能卡住的通道交给别人。连接只在入池的那一刻才与打开它的操作的上下文脱钩，所以终端与流式操作仍然随撤销 / 到期关闭自己的传输。复用不改变授权：每个操作仍然带着自己的批准单。连接按"保存连接 + 已核对主机指纹"分键，入池的连接每秒清理一次、空闲超过 15 秒即关闭，资料 / 策略变更或锁定也清空并关闭。

已知边界：路径检查与真正使用之间存在 TOCTOU，远端同一账号下的独立进程可以在这段时间里替换符号链接（SFTP v3 没有 `openat` 那样的一次性语义）；所有者的操作按设计不受路径策略限制，因为所有者本来就是信任根，代价是桌面进程内的任何代码都等同于所有者。
