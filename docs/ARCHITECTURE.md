# 架构

## 网关内核、管理端与调用方 · 2026-10-22

本节是后续实现的职责与验收基准，不代表下列策略和审计接口已经实现。现有代码状态及缺口见本节末尾；下方历史章节保留既有实现说明。

内核定位为供人和自动化共用的本机 SSH 访问网关，集中处理凭据使用、目标身份校验、授权、执行、撤销和审计。桌面是所有者的完整管理客户端；CLI 是入口形式，既可以承载已验证的人类管理操作，也可以承载 AI 的受托操作。禁止根据窗口类型、命令名称或调用方自报标签决定权限。

```text
所有者 → 桌面管理台 / 人类管理 CLI ─┐
                                  ├→ 网关内核 → SSH / SFTP → 服务器
受托调用方 → CLI / 将来的其他接口 ─┘
```

### 身份和职责

第一版只有所有者和受托调用方两类权限主体，不引入团队管理员或独立审计员角色。内核是执行组件，不是能够给自己授权的用户。桌面同时提供服务器操作界面和权限管理界面，二者调用内核的不同能力。

| 主体 / 入口 | 可以使用什么 | 可以管理什么 | 可以查看哪些记录 |
| --- | --- | --- | --- |
| 所有者，通过桌面验证 | 自己的服务器操作，仍受服务器账户权限限制 | 连接、凭据引用、调用方配对、策略、授权、撤销和审计设置 | 所有经过本内核的活动；详细内容受记录设置约束 |
| 所有者，通过终端验证 | 与所有者权限一致的终端操作 | 无桌面时的管理入口；管理操作仍需有效所有者证明 | 所有者认证后查看全局记录 |
| 已配对 AI / 自动化客户端 | 授权范围内的服务器、操作和期限 | 申请授权、取消自己的任务、撤回自己的授权；不能批准、扩权或修改管理设置 | 仅自己的请求、结果和必要的拒绝原因 |
| 未配对客户端 | 最小配对引导与申请回执 | 无 | 仅自己的配对 / 申请状态，不枚举服务器或全局活动 |

所有者权限来自主密码或系统验证建立的所有者会话与具体请求证明；受托权限来自绑定客户端密钥的授权。客户端密钥证明持有者身份，不证明某个软件品牌、模型名称或当前操作者一定是人。AI 使用 CLI 不获得人类管理权限；人类管理 CLI 也不能只凭 `--owner`、`--client 用户` 或已有受托会话切换为所有者。

第一版不向任何客户端返回可导出的 SSH 密码、私钥、密码管理器会话或保险库密钥。人类管理端配置和使用凭据；受托方只得到使用能力。客户端请求与服务器返回内容属于不可信数据，可供所有者审阅，但不得被当作管理指令或自动授予权限的证明。

### 谁使用权限与审计功能

所有者使用桌面的“访问管理”入口，按需进入“调用方”“权限”“活动记录”。保留左侧连接和中间终端为主要工作区，不增加常驻安全面板。服务器详情可就地进入该服务器的访问规则，全局入口使用同一模型。

- 调用方：配对、公开密钥指纹、授权范围与期限、活动状态、撤销。
- 权限：服务器允许 / 询问 / 禁止受托访问；明确的操作范围、受保护资源与需要批准的升级操作。禁止规则优先于有效授权。
- 活动记录：谁申请或执行了什么、涉及哪台服务器、规则判断、结果与时间。默认突出受托请求和异常，也能查看所有者自己的操作；查看和筛选不需要每条重新输入密码。

调用方只使用申请、执行、自身状态、取消接口，不使用全局权限配置、全局授权队列、全局审计读取或清理接口。即使没有桌面，已验证的所有者也能通过管理 CLI 审批和撤销；仅供所有者使用的交互验证不能由 AI RPC、命令参数或环境变量替代。

### 执行和授权边界

管理面负责配置和查看，执行面负责实际放行；所有检查在内核完成，不能只在桌面隐藏按钮。所有者明确进行的人工操作可复用已解锁所有者会话；这一状态不自动批准排队的受托请求。批准外部能力或扩大权限沿用明确确认与必要的系统验证。

受托请求的处理顺序为：验证调用方证明 → 按已保存的连接 ID、目标及指纹离线核对绑定 → 检查服务器规则与授权范围 → 检查具体操作 → 记录决定 → 执行或拒绝 → 记录实际结果。禁止服务器在任何目标探测、网络连接和凭据使用之前拒绝，不弹窗；只向请求方返回必要原因，所有者活动记录显示警告。策略版本变化需阻止旧请求启动，并取消受到新禁止规则影响的受托会话，不能等待旧授权自然到期。

长授权只免去范围内的重复人工确认，不能跳过后续策略检查。自动保活、状态采样和单纯读取任务状态不得自动延长授权；自然到期后再次尝试使用才申请原范围续期，拒绝、撤销和禁止规则不自动发起新申请。连接和任务按授权主体隔离，停止 AI 会话不关闭所有者的人工终端，也不把原始共享连接或控制套接字交给调用方。

结构化文件 / 服务操作可以在执行前检查明确目标；任意 Shell、脚本、提权和 Docker 管理不能靠字符串过滤证明符合路径规则。需要强制保护关键目录时，应限制可用操作并配合服务器专用账户、目录权限或受控执行入口。保护包含删除、覆盖、移动、属性变更和关联父目录等影响；服务器路径解析与竞态不能只靠本地字符串前缀判断。

撤销授权需要停止新操作并取消现有访问，但不能把“SSH 已断开”记为“远程任务已停止”。远端已脱离会话或交给 systemd / Docker 等管理的任务可能继续。遇到断线且结果不明时，记录结果未知，重新查询实际状态；不自动重放写操作。

### 审计边界与可见性

第一版以操作级事件为主：可信调用方标识及身份类型、服务器 / 授权 / 请求关联、动作、策略版本和命中规则、允许 / 拒绝原因、开始结束时间、实际结果或退出码。调用方自报名称仅用于展示。元数据应记录人工操作和策略变更；任务结束与任务成功分别表示，未获执行权限的拒绝也要留下事件。

凭据、授权票据和密码管理器会话永不记录；命令参数、路径和输出可能含敏感内容，原始详情采取最小化和所有者可控的记录策略，不能承诺任意输出都能被自动脱敏。包含详情的持久记录需要独立的加密存储、读取授权、保留期限和清理规则；导出及删除记录属于所有者管理操作，并记录自身事件。只保留元数据时，界面必须明确不能恢复完整命令或输出。

实时旁观和持久记录分别设计：受托任务可以把同一份输出送回调用方并同步给所有者查看，但观看不等于自动落盘；所有者在独立 AI 任务视图停止或撤销，不能与 AI 同时向同一个交互终端无协调地输入。

全局请求、历史和审计查询必须验证所有者身份；受托查询必须核对请求归属及有效证明，不能以知道请求 ID 或能访问本机 socket 为依据。权限中心不是凭据导出接口。应用层读取限制不能被描述为抵御同 OS 用户任意文件访问；强隔离需要额外账户 / 进程与存储保护。

### 自动采样不逐次进入操作审计

内置服务器状态采集属于已授权会话的固定内部工作：CPU、内存、网卡 / 流量、磁盘 / 挂载点、进程、服务清单，以及 Docker / Compose 清单和资源数据，不按采样次数创建审批请求、写命令审计或持久保存原始结果。`hosts/pending/status` 等界面状态轮询同样不逐次写操作日志。保留外层会话的批准、开始、撤销和结束等生命周期事件。

采样免于逐次审计不免除授权、目标校验、速率预算或取消处理。内核内置执行路径与固定命令允许列表是可信边界；调用方不能用自报名称、`ServerStatus`、`Kind=exec`、相同命令文本或可传入的 `noAudit` 标记获取豁免。相同固定命令由人工 / AI 单独请求执行时，仍按普通操作记录。

当前自动采样和重复失败重试本来就不写逐次审计；失败通过当前状态反馈和退避处理。后续如增加持久健康诊断，只记录首次失败、恢复或有界汇总，同一目标 / 探测种类的重复失败合并计数，不保存无限逐次错误。正常指标流与健康诊断不混进操作审计。

人工生成服务器概览、主动浏览文件和查看日志等操作仍受所属主体的授权与记录规则约束；文件写入 / 删除、终止进程、服务与容器启停、Compose 更新、权限变更、批准 / 拒绝 / 撤销均不能因位于“服务器状态”页面而被过滤。管理动作内部伴随的核对读取关联外层操作，不把其每个内部命令重复记录。权限拒绝必须保留；大量重复拒绝可有界合并，但不能完全隐藏或丢失首次 / 最后时间与累计次数。


### 当前代码状态和实施顺序

- 已有：所有者证明、精确操作票据、客户端密钥委托、目标和指纹绑定、期限与撤销、共用 broker、服务器受托禁入、关键路径策略、持久历史与有界轮转。路径保护拒绝任意命令和终端，允许的结构化写入再检查远端规范路径，不把命令黑名单当作保护。
- 尚无：完整操作输出 / 退出结果回放、桌面实时旁观、可对外登录的 SSH 网关入口。
- 优先修复：`pending` 直接返回全局请求；`status/sessionStatus` 未按调用方隔离；`hosts` 返回全局公开连接资料。当前可访问本机 IPC 的客户端可能看到其他请求的命令和路径，不能宣称“受托方只看自己”。
- 当前“历史”通过一次性所有者证明分页读取持久事件，包含服务器与申请方、策略 / 范围 / 无效证明拒绝原因、请求 / 批准 / 撤销 / 到期和执行开始 / 结束。可信本机来源与自报标签分开；`ended` 只表示结束，不等于执行成功。命令、文件路径和输出不落盘，尚不提供完整结果回放。
- 实施顺序：先补管理读取与调用方归属 → 增加服务器规则和统一决策入口 → 完善有界的事件 / 结果审计及管理视图 → 增加旁观和受控操作规则；远程部署与外部 SSH 客户端接入单独设计。

验收至少覆盖：伪称桌面不能提权；受托方不能读取全局或其他调用方请求；经验证的人类 CLI 可以管理；禁止服务器不访问目标、不弹窗并留事件；禁止规则修改阻止已有授权继续使用；授权内普通操作不重复弹窗；策略和实际结果可追溯；断线不伪报远端取消；强路径保护不由任意 Shell 黑名单冒充。

桌面共享组件已经落地到 `internal/desktop/components`，按钮、操作组、弹窗、目录树、文件列表和排序表格在现有页面复用。具体职责、使用约定与离线展示页见 [基础组件](COMPONENTS.md)。下方旧提案中的凭据实体拆分仍属单独的模型迁移。

服务器状态扩展了独立 Docker 资源采样、主机 / 容器共用资源呈现和受确认约束的管理动作。组件新增 Surface / Metric / 分段表 / 环形表 / 虚拟卡片网格；业务层保留具体动作与目标快照，`internal/serverops` 仅生成白名单命令。管理动作通过原有 broker 和所有者证明；Docker 固定本地 socket、实例及完整容器 ID，管理请求还约束当前终端 endpoint 与主机指纹。详见 [服务器状态与操作](SERVER-MANAGEMENT.md)。

```text
MyGo 原生桌面 / 人类 CLI / AI 调用 CLI
              │ 私有本地消息协议
              ▼
共享代理：加密保险库、授权队列、单次票据、会话取消、审计
              │
              ▼
Go SSH / SFTP → 目标服务器
```

`cmd/ssh-client` 是无界面的入口，`cmd/desktop` 是桌面入口。桌面解锁后在同一进程托管代理；无桌面时由 `smallssh agent` 托管。两个入口的网络操作都通过 `internal/client` 和同一代理协议，桌面不另建 SSH 权限通道。

`internal/vault` 使用 Argon2id（3 次、64 MiB、1 lane）和 AES-256-GCM 加密整个连接集合。每次写入使用新 nonce，版本、盐和库 ID 纳入认证附加数据。连接更新先提交加密文件，再发布到内存。文件锁阻止两个代理同时写同一个库。

`internal/approval` 将主机 ID、代理填入的实际连接目标与主机指纹、操作、命令、路径、新旧内容摘要和到期时间绑定到不可变请求。调用方只能拿到自己的随机票据；批准需要保险库派生的 HMAC 证明。票据仅能消费一次。主密码不会通过 AI 协议传递。

`internal/broker` 执行获批操作，限制连接数和消息大小，分块流式传输。授权到期、撤销、锁定及客户端断开会取消上下文并关闭 SSH。更新连接会使旧授权失效，防止批准的是旧目标而执行时使用新目标。

`internal/sshconn` 支持密码、私钥、指定 SSH agent 身份及强制 SHA256 主机指纹校验。SSH agent 只对明确选中的一把公钥请求签名。没有全局跳过主机身份检查的开关。

`internal/desktop` 使用 MyGo 原生组件、代码编辑器和官方 terminal 插件。终端插件内部使用固定版本 libghostty-vt。桌面包含连接设置、多终端、文件与编辑、授权中心以及独立授权弹窗。系统锁屏/休眠通知会尝试锁定代理。

`internal/systemauth` 是本机所有者入口的系统认证层：macOS Secure Enclave / LocalAuthentication、Windows Hello interop / DPAPI、Linux fprintd / Secret Service。验证后临时打开保险库，为本次请求计算证明，然后关闭临时会话。系统验证取消时失败，用户可另行选择主密码。

`internal/transfer` 供桌面和 CLI 共用。私有目录保存任务、进度与摘要，运行票据只驻留内存。每次恢复创建新的授权请求；持有票据的客户端可撤回自己的请求，不能批准或扩大权限。`internal/sshconn/resume.go` 管理部分文件与无覆盖提交。

`internal/monitor` 解析固定 Linux 采样结果；代理每两秒通过 SSH 执行并流式发送结构化数据，无需在服务器安装守护进程。以 /proc 的累计计数差计算各核心与网卡速率，以 /sys/block 的 512 字节扇区计数计算块设备吞吐、IOPS 和忙碌率；排除 loop / ram 等设备和存在下层从设备的逻辑聚合层，避免对同一 I/O 重复累加。默认网络图跟随默认路由网卡，详情可选择其他接口。首样本、计数回退或新设备没有速率，图表留空；进程清单使用 ps 的 CPU / RSS 排序结果，明确其平均值语义。

桌面的 `status_chart.go` 提供共享的时间轴、面积 / 折线、图例与悬停绘制；`status_resources.go` 组织资源卡片、CPU / 内存 / 网卡 / 磁盘详情与系统信息。每个终端 session 保存最近 15 分钟、最多 451 个紧凑点，只有曲线需要的字段，不保留进程清单、系统清单或终端输出副本。状态图不写磁盘、不创建后台刷新动画，仅在采样或界面交互时更新。乱序、重复、旧解锁代际、已关闭和已移除会话的回调不能污染历史；缺样本大于 8 秒时折线分段。

## 连接体验与组件分层方案 · 2026-10-20

本节保留设计提案；下方“本轮落地”记录目前已实施部分。独立凭据模型迁移仍未完成。

### 重构前的实现与问题

- 密码、私钥、私钥口令与每条 `vault.Profile` 一起加密保存；没有独立的凭据实体、复用关系或凭据管理页。
- 新建连接支持密码、私钥和指定 SSH agent 身份；界面直接暴露内部连接 ID、手填主机指纹及英文登录方式，默认表单过长。
- 私钥导入通过系统文件选择器选文件，保存时读取到保险库；完整解析和口令校验要等真正连接时才发生。尚无密钥生成、导入预检和使用关系管理。
- 编辑连接仅允许改基本信息，不能在相同流程中更换认证方式或凭据。
- 底层已有加密存储、权限代理、SSH / SFTP、传输、监控和系统认证边界；应保留这些边界，拆解当前集中在 app 状态中的界面逻辑。
- MyGo 已提供 Form / Field（含 Description、Error）、TextInput、Select、List、Tree、Table、Tabs、Split、Menu、Modal、文件对话框及编辑器。当前手工固定标签宽度的 field 函数应优先改用已有表单组件。

| 服务器状态 | 概览、四类资源详情、进程、自启服务、系统信息 | 趋势卡片、时间轴与悬停、详情指标、搜索排序表格、服务列表、更新时间及失效状态；按需展开并恢复终端空间 |
| 凭据管理 | 密码、私钥、代理身份、引用关系 | 凭据列表与详情、私钥导入预检、密码 / 口令输入、使用关系、删除前影响确认 |
| 授权与安全 | 解锁、批准、撤销、审计 | 操作范围说明、所有者确认、授权状态列表、审计列表 |
| 应用框架 | 菜单、侧栏、会话区、工具面板、偏好 | 动作注册、可停靠面板、统一加载 / 空态 / 错误态、设置分组 |

产品默认仍是左侧连接列表、中间终端，下方可收起工具面板。凭据和设置从菜单进入；新建连接时也能就地新增或选择凭据，不要求用户先离开当前流程完成另一套管理步骤。

### 主要操作流程

1. 新建连接只展示名称、地址、用户名和登录方式。连接 ID 自动生成；端口默认 22，分组可选，高级项折叠。
2. 登录方式选择“服务器密码 / 已有私钥 / SSH 密钥代理”，使用中文说明；凭据可以就地输入或选择。规划支持仅本次使用，临时材料不落盘。
3. 首次连接展示主机身份供用户核对，支持保存已经核对的指纹；已有记录一致时复用，变化时阻止连接。不能把网络探测结果直接当作可信身份，也不取消当前的主机校验。
4. 一次连接授权明确包括终端和固定只读状态，沿用现有所有者确认与权限代理。尚未设计并批准新的授权策略前，不自动跳过当前确认。
5. 连接成功进入终端，自动刷新服务器状态；文件、传输、常用命令随需要使用。

私钥导入：系统文件选择器 → 本地识别算法 / 格式 / 加密状态 → 按需输入私钥口令并预检 → 派生公钥指纹 → 命名并加密保存 → 连接引用。正文不进入列表、日志或 AI 协议，不把私钥传到服务器。

“创建密码凭据”只是保存已有服务器用户名 / 密码；不修改服务器账户。“生成新密钥”是另一项本地能力，生成完成并不自动获得服务器登录权限。向服务器安装公钥需要已有登录渠道与明确的独立授权，不能在导入或生成时偷偷执行。

必须明确区分四种信息：保险库主密码 / 系统指纹用于本机解锁和所有者确认；服务器密码用于 SSH 登录；私钥口令用于解开私钥；主机指纹用于确认服务器身份。

### 组件边界

| 层级 | 责任 | 放置方式 |
| --- | --- | --- |
| MyGo 基础控件 | 排版、表单和字段错误、输入、焦点、列表虚拟化、菜单、分栏、对话框、可访问性 | 直接复用固定版本已有 API，不另造基础控件 |
| 项目内组合组件 | 可关闭会话标签、可停靠工具面板、文件浏览器外壳、资源选择器、统一状态反馈、任务进度行 | 先在项目 components 中复用；只接收数据和回调，不导入 SSH / 权限服务 |
| SSH 业务模块 | 连接表单、凭据与私钥流程、主机信任确认、授权语义、服务器状态与生命周期 | 留在客户端 features 模块；每个模块分视图、状态和动作 |
| 无界面服务 | 保险库、认证、权限代理、SSH / SFTP、监控、传输恢复、审计 | 桌面与 CLI 共用；不依赖 UI 状态 |

可停靠面板、文件浏览器、资源选择器等组合控件，先经本项目多个位置使用，稳定键盘、焦点、取消、加载、错误和性能行为后，再评估抽为 MyGo 生态组件包。SSH 凭据语义、服务器连接和权限策略不适合塞进 MyGo 核心。

规划的数据模型将 Connection（目标、用户、选项、凭据引用）、Credential（加密材料及公开摘要）、HostTrust（已核对的服务器身份）、Session（本次运行状态）分开。界面只能获得凭据公开摘要；密钥材料由代理解析使用。迁移需兼容已有内嵌凭据，不能丢失旧连接、明文导出或静默改写授权范围。

### 实施顺序与验收

用户明确要求先用测试凭据走通新建 / 编辑和加密存储体验，再由其在正式界面录入真实连接。真实 512MB 服务器状态验收随之延后；之后再拆出凭据管理、提取经过复用的组合组件。不会同时重写终端渲染与 SSH 底层。

连接验收需包括：可取消的连接、密码 / 私钥 / agent 三条路径、错误口令与格式反馈、首次身份核对与变更拒绝、保存 / 临时使用、编辑凭据后的引用影响、锁定及授权撤销、终端与状态不串会话。真实状态验收需从服务器独立命令核对 CPU、内存总量与使用量、进程 PID 与占用，并观察连续多次自动刷新。

参考：[FinalShell 功能与监控](https://www.hostbuf.com/t/988.html)、[FinalShell 常见问题](https://www.hostbuf.com/t/1088.html)、[Termius 的 Hosts 与 Keychain](https://www.termius.com/)、[MobaXterm 的会话、密码与私钥管理](https://mobaxterm.mobatek.net/documentation.html)。参考其职责划分和成熟流程；不照搬会员、云同步、停用远程历史或额外 SSH 登录等具体策略。

### 本轮落地 · 2026-10-20

连接表单改用 MyGo Form / Field，内部 ID 自动生成，端口显示在地址旁，分组为可选已有 / 新建的可编辑下拉框，登录方式使用中文。主机身份由未进入认证阶段的密钥交换探测提供，用户核对后才保存；身份绑定到确切地址及端口。私钥导入预检格式和口令，代理身份只列公开信息供选择。编辑提供保留 / 更换凭据，已存凭据不回读到界面。

保存和凭据替换选项参与单次所有者签名；成功落盘后才使该主机的授权失效，其他主机会话保留。保存及直接连接复用桌面进程内已解锁会话的所有者证明，不缓存或重复要求主密码；首次主机身份在独立页面明确确认，随后连续执行保存 / 连接并返回终端。证明只批准该次终端及只读状态，不批准其他排队的 CLI / AI 请求；锁定或退出撤销会话。取消和离开表单清理输入，异步结果经过操作序号及会话世代校验。

原生文件选择器移到渲染回调之外等待，避免嵌套事件阻塞 UI。无窗口测试在系统选择器边界注入选择 / 取消结果，覆盖实际按钮到导入、预检、加密保存和登录；不把它描述为真实系统弹窗操作验收。另提供可粘贴本机完整路径的私钥文件输入，与选择器共用后续流程。用户工作期间不通过重启或菜单操作验收弹窗。

新增身份变化后的重新核对入口和连接错误说明；重新核对不会自动信任新身份。提交加密保存时禁用侧栏导航，防止切换服务器把正在提交的表单隐藏。无窗口 UI 测试连接真实本机 SSH 服务，覆盖密码、普通 / 加密私钥、关闭重开代理、原私钥文件移除、错误密码重试及连接中取消；离线界面快照不运行 App、不创建系统窗口。

凭据仍内嵌在连接中加密保存，独立凭据列表、跨连接复用、仅本次凭据及密钥生成属于后续工作，不列为已实现。

### 静默开发重启

`tools/dev` 封装固定版本的 MyGo watcher，每轮子进程继承后台模式及独立数据目录。`cmd/desktop` 的普通开发构建也默认后台启动。`startupState` 每次启动重新生成实例标识并清空可见许可；事件循环启动前设置 accessory 策略，主窗口以 Hidden 创建，从源头避免默认 Show 和启动激活。窗口状态文件不存“下次自动显示”。

`internal/desktopcontrol` 提供单独的当前用户私有 IPC，仅接受状态、明确显示和正常退出。处理器派发到 UI 线程，状态查询只读可见 / 焦点属性；唯一的显示分支才恢复 regular 策略及显示 / 聚焦。该接口与 SSH broker 和所有者批准完全分开，退出确认先送达再触发 App.Quit。后台未明确显示时不创建授权弹窗，不把隐藏请求当作已经通知或批准。


### 全流程审查后的交互与授权边界

本机界面的明确操作统一使用 `Client.RequestWithOwner / StartWithOwner`，传输使用 `RunWithOwner`。这三项需要进程内 `vault.Session`，先签名一次性创建挑战，再批准具体不可变请求；公共 CLI 请求仍通过单独验证。代理签发 `ownerIssued` 标记供 UI 排除自身授权弹窗，只有本机 shell 才派生持续会话标记，文件任务和外部请求仍有期限。

界面仅保留与当前任务相关的信息：授权页显示服务器、来源、命令或路径，签名摘要与请求标识收在技术详情；文件窗口自动读取并就近重试；提示可关闭，常驻开发说明删除。未保存的连接需要明确放弃，异步连接不会盖掉新的表单；已有终端复用，重连成功才替换旧标签。后台任务与授权回调均受操作上下文及会话世代约束。
