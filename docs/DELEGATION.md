# 有期限的客户端会话与一次性子授权

客户端先申请指定服务器的会话，由所有者在桌面授权中心或可信的人类终端核对权限、期限、配对码后批准。此后每项操作由代理签发一次性子票据，不再逐项等待批准。默认 2 小时绝对期限、15 分钟闲置期限；允许显式配置为 1 分钟至 8 小时，闲置最多 30 分钟且不超过绝对期限。

本地加密密码库继续可用。当前委托机制基于本地密码库的所有者证明。1Password / Bitwarden 后端、外部密码库的按需解锁与会话续期均尚未接入；本地 AI 委托测试通过不等于这两种后端可用。此前的目录写入限制是历史阻碍，本次已可正常修改工程，剩余工作仍需实际实现和验收。

桌面授权弹窗首先显示申请方、服务器、权限和期限。申请方名称来自客户端自报，不能当作验证过的软件身份；会话申请需要与申请端核对配对码。只读范围包含该 SSH 账户有权访问的所有路径；读写范围还受服务器策略约束，保护开启时明确提示不开放任意命令、终端、属性及续传写入。单次命令的完整内容保持可见和可滚动，指纹、摘要、配置来源和请求编号默认折叠。

## 使用

先启动并解锁桌面端或可信终端代理。申请端运行：

```sh
smallssh --client '我的 AI 工具' session request server-id my-ai.json read 2h 15m
```

在所有者界面核对该命令显示的配对码，确认服务器、权限和期限，再批准。客户端名称是自报信息；配对码对应申请端生成的 Ed25519 公钥，表示后续请求需要持有相应客户端密钥，不表示已经验证某个软件厂商或进程的身份。

批准成功后，客户端文件保存在数据目录的 `client-sessions/`，可用文件名或该私有目录内的绝对路径引用：

```sh
smallssh --session my-ai.json ls server-id /srv
smallssh --session my-ai.json get server-id /srv/example.log ./example.log
smallssh session status my-ai.json
smallssh session revoke my-ai.json
```

一个已批准会话覆盖该客户端在指定服务器、权限和有效期内的连续操作，不逐条询问。AI 工具可以在自己的环境中设置一次会话文件，后续 CLI 调用自动复用：

```sh
export SSH_CLIENT_SESSION=my-ai.json
smallssh ls server-id /srv
smallssh get server-id /srv/example.log ./example.log
```

环境变量只选择已经持有的会话文件，不搜索其他客户端的权限，也不根据自报名称匹配授权。显式 `--session` 优先；显式 `--session=` 可退出环境选择，创建单次请求。环境选择只用于远程操作和传输续传，不影响会话申请 / 状态 / 撤销及所有者管理。文件缺失、被撤销、被拒绝或超出范围时直接失败，不静默降级为单次审批。自然过期按下面的续期流程处理。

桌面只为新的客户端会话申请自动弹窗；普通单次请求进入授权中心并显示数量，仍需所有者明确批准才能执行。同一批会话申请只弹出一项，其余保留在中心；已有弹窗或一分钟提醒间隔内出现的新申请也只进入中心，不会在稍后连着弹出。提醒合并不会批准、延长或扩大任何权限。已批准的子操作不再打印“等待授权”。

`read` 只允许列目录、下载和固定服务器状态采样等受控读取，不提供任意命令或 Shell。它不限制可读路径；远端文件访问仍由 SSH 账号的权限决定。读写操作需明确申请 `full`：

```sh
smallssh --client '我的 AI 工具' session request server-id maintenance.json full 30m 10m
smallssh --session maintenance.json put server-id ./new.txt /srv/new.txt
```

服务器默认开启关键路径保护。`full` 不绕过该策略：允许的受控文件写入还会核对源、目标、规范路径和符号链接。任意命令 / Shell、容器终端、Compose 更新、属性修改及续传写入在保护模式中直接拒绝并留历史。需要任意命令和终端时，所有者须在该连接“AI 访问…”中明确关闭保护并确认风险；这会开放 SSH 账户的完整能力，不承诺在 Shell 内阻止删除或提权。关闭该连接全部 AI 访问则不创建审批，只记录拒绝。`--session` 不会静默降级到普通排队请求；撤销、拒绝、超出范围或文件损坏时直接失败。

授权中心“历史”展示持久操作元数据，锁定和重启不会删除已保留记录。策略拒绝、超出授权范围和无效证明可查原因；自报申请方与可信本机操作分开呈现。历史不记录原始命令、文件路径或输出，最多保留两个8 MiB文件。详细边界见 [安全与边界](SECURITY.md#关键路径保护)。

## 自然过期后的按需续期

绝对期限或闲置期限到期后，旧授权立即失效，正在进行的子任务按原规则终止。下一次范围内的实际操作会自动用客户端密钥证明身份，申请沿用原服务器、主机指纹、权限、最长时间和闲置时间的续期。没有实际操作时，不会靠后台计时不断询问。只读授权遇到写操作会直接拒绝，不借续期扩大权限。

多个并发调用等待同一份续期申请，所有者批准后各自领取新的子票据并继续。只重试尚未开始的授权步骤，不重新执行已经开始或被中止的命令、写文件或传输。会话文件及客户端密钥不需要替换。

每轮续期都生成新的审批 nonce，弹窗和系统验证明确显示“续期”。所有者前端只为实际展示的那一轮申请签名；旧审批、旧子票据、旧挑战不能恢复权限。续期持有者证明使用独立的 30 秒一次性挑战，服务器串行合并创建请求，审计记录区分每一轮 nonce 的摘要。

拒绝、主动撤销、连接配置改变、锁定或退出后不会自动申请续期。未处理的续期申请五分钟后失效，不后台循环重新申请；之后再次实际使用可以重新申请。续期所需的旧范围记录只在当前代理内存中保留，最多 256 项；锁定、退出、重启或记录淘汰后，需要显式建立新会话。旧范围记录不具备执行权限，也不会把未知或失去记录的客户端视为已批准。

## 安全边界

- 父授权仅在代理内存中存在，重启、锁定和退出后失效。客户端文件不包含 SSH 密码、SSH 私钥、保险库密钥或密码管理器会话；但它包含本客户端的签名密钥及撤销自己会话的票据，必须作为敏感授权文件保护。
- 文件只能位于代理的 `client-sessions/` 私有目录，创建使用排他方式，禁止覆盖已有文件和跟随最终文件的符号链接。Unix 要求私有目录及文件权限；Windows 沿用代理目录的当前用户 SID 保护。读取检查普通文件、大小、文件身份及客户端密钥一致性。
- 每次领取子授权使用 30 秒一次性挑战。签名绑定父授权 ID、完整操作、服务器端点、已信任主机指纹、期限及挑战随机 ID。另一客户端即使使用相同名称也不能领取；失败、成功、重放或到期后的挑战均不能复用。
- 子授权最多 5 分钟且不能晚于父授权到期。子票据仅能启动一次，不能审批其他请求、延长父授权或再创建下一级授权。短期操作的完成不延长父授权的绝对期限；成功签发操作会刷新闲置时间。
- 父授权撤销会取消已有子任务、废弃待签名挑战并阻止续发。绝对或闲置到期由代理每秒检查；绝对期限也约束子任务上下文。修改或删除服务器配置时沿用原有服务器授权失效逻辑。
- 上传、下载和续传仍绑定原有路径、内容摘要、传输 ID 及偏移检查。单次子任务最多运行 5 分钟；长传输可使用同一有效会话重复续传，无需再次人工批准。
- 审计仅记录授权 ID、父授权 ID、服务器 ID、操作类型和操作摘要，不写入客户端签名密钥、票据、命令、文件路径或输出。授权文件不代表可抵抗已控制同一 OS 用户的恶意进程；操作系统用户仍是本机信任边界。

## 隔离验收

测试使用生成的密钥、隔离密码库和回环 SSH，不读取真实密码库，不启动原生窗口。覆盖所有者批准、客户端持有者证明、配对码呈现、权限及目标收窄、签名字段篡改、挑战与票据重放、并发消费、父子期限、闲置刷新、级联撤销、配置变更、真实 SSH 命令，以及经原续传管线下载和拒绝上传。
